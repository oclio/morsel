# Security Policy

We take the security of our open-source tools and packages seriously. If you believe you have discovered a security vulnerability, we appreciate your help in disclosing it to us responsibly.

## Supported Versions

Only the latest major version of each package is actively supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| Latest  | :white_check_mark: |
| Older   | :x:                |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, please report any security vulnerability by emailing us at:

👉 **[security@oclka.dev](mailto:security@oclka.dev)**

### What to include in your report

To help us better understand and address the issue, please include as much of the following information as possible:

- The name and version of the affected package(s).
- Type of issue (e.g., buffer overflow, RCE, credential exposure, path traversal).
- Step-by-step instructions or a minimal reproducible example to demonstrate the vulnerability.
- Any potential impact or potential fix you might have identified.

## Response Process

When we receive a vulnerability report via `security@oclka.dev`:

1. **Acknowledgment:** We will aim to acknowledge your report within 48 hours.
2. **Assessment:** We will investigate and confirm the report's validity.
3. **Fix & Release:** If validated, we will work on a patch and release a security update as quickly as possible.
4. **Disclosure:** Once a fix is released, we will give proper credit (if desired) and publish details of the security advisory.

Thank you for helping keep the `@oclio` ecosystem safe!
